## hover-gate.cjs — `npm run audit:hover` (customer rule 2026-11-13)
Rule: EVERY button-like element has the "disc from the centre" hover (see `design-system.md`, "Кнопки: hover" and the DISC block at the end of `src/styles/components/buttons.css`). The gate makes that impossible to skip.

What it does: opens all pages (index, about, services, catalog, product?slug=anastrozole, contact, privacy, terms, data-processing, faq, impressum, 404, design-system) at 1440 and 375 with headless Chrome (puppeteer-core, one browser per worker), collects every `a, button, [role=button|option|tab], summary, input[type=submit]`, classifies it and checks it with a REAL mouse hover (waits 950 ms > `--dur-hover-disc`):
- **button-like** (opaque fill, border, `.btn*`/`.round-btn*`/`.icon-ring--action`/`.nav-pill`/`.lang-switch`/`.filter-item`/chips/…, or contains a round button / action ring): (a) a `::before` disc whose scale goes 0 -> 1 (on the element or on its ring/round-button child); (b) label contrast >= 3 against the disc/surface at the end; (c) visible change: dE(CIELAB76) >= 10 between rest and hover (label colour or the pixel at the left edge); (d) size unchanged; (e) FRAME: for the pill role (`.btn--secondary/.btn--ghost/.nav-pill/.lang-switch/.header__burger/.filter-item/.catalog__filters-toggle/.lang-menu__option`) a 1px opaque `--accent` border on hover, visibly different from rest (transparent reserved border) or already opaque at rest.
- **speed (one for all instances)**: for every tested disc, the computed `transition-duration` of `::before` (`scale`) (and the owner's `color` where it changes on hover) must equal the token `--dur-hover-disc` (+-1 ms) with `transition-delay` 0, otherwise FAIL (`discDuration`); the owner's colour/frame flip uses the colour tokens instead (`--dur-hover-color`, delay = `--delay-hover-color-in` or `--delay-hover-color-round-in`, rule B2b). Easing is the token `--ease-hover` (one definition; no page CSS may override duration/easing/delay of the disc). Applies to element rows and to `card-hover` rows.
- **coverage time (rule B2b, "ховер кнопок як на решті")**: for every disc: time from hover start until the disc radius reaches the farthest point of the button's padding box (rounded corners included), computed from the real geometry (`::before` width, button size, border radius) and the disc's own easing curve (`coverMs`, token `--disc-overscan` sets the geometry in the DISC block of `buttons.css`: disc = covering circle x overscan for EVERY form, round and long alike). After the crawl the gate takes the median `coverMs` per width and every disc must be within +-10% of it, otherwise FAIL (`coverage`, `covered` = the disc must reach full coverage at all); the run prints `coverage @W: median/min/max`. Not compared (reported as `coverSkipped`): text links (own radial-gradient fill), the active language option (instant by design) and a label that wraps to several lines (taller than the control height `--_h` the geometry is built on). No allowlist exception for this check.
- **text-link** (ONE component `components/text-link.css`: footer links + group titles, breadcrumbs `a`, inline prose `a:not([class])`; customer 2026-11-13 "нехай буде заливка фону кнопки", rule B6): fill lighter than the surface grows from the centre (`::before` plate scale 0 > 1; prose links, which wrap, get a background-color fill); gate checks: `disc` (radius animates), `discDuration` (= `--dur-hover-disc`, delay 0), `lighter` (fill luminance > surface), `visible` (pixel dE >= 1, same relaxed threshold as `.contact-line`), `noDecoChange` (computed text-decoration equal at rest and hover), `colorSame` (text colour unchanged), `label` (text/fill contrast >= 4.5), `size` (no jump).
- **other text link** (not in the component): visible hover (label dE >= 10, or underline change, or fill change); no disc required.
- **card / media links** (contain img/heading/p): reported as N/A (hover owned by the component).
- **Cards with one action button** (`CARDS` in the script = the `:is()` list in buttons.css): hover on the card BODY (not on the button) must produce the disc on its button (`card-hover` rows; now also `.product-card` and `.link-card`, with the same speed check).
- Forced-state demos in design-system (`.is-hover/.is-focus/.is-pressed/.is-disabled`) and disabled controls are N/A.
- Extra scenes: 1440 = language dropdown opened; 375 = burger menu opened (index, catalog, contact).
`.contact-line` rows (About/Contact/footer; one component, no underline, fill `--surface-white` = a step lighter than the host surface) are checked as buttons with a relaxed visibility threshold dE >= 1 (instead of 10) plus a `lighter` check (disc luminance > surface, text-decoration none at rest and hover); no allowlist entry. Exit code != 0 on any FAIL/ERROR. Exceptions only in `hover-gate.allowlist.json` (`selector`, `reason`, optional `pages`/`widths`); every entry needs a reason.

Usage: `npm run audit:hover` (starts its own vite on 5191 and stops it) or `node tools/hover-gate.cjs --url http://localhost:5173 [--pages index,about] [--widths 1440,375] [--workers 1] [--verbose] [--all] [--inventory out.json]`. `--inventory` writes every checked row + the full clickable list. `CHROME=/path` overrides the Chrome binary.
New button-like element: add it to the role list in the DISC block of `buttons.css` (do not write a separate hover) and run the gate.

Note: run it with <= 3 workers (default); more parallel Chrome windows throttle transitions. Do not run two gates at once on one machine.

## style-gate.cjs — `npm run audit:style` (customer: "мені потрібен гейт"; spec: `content/audit/trust-audit.md`, section B)
Browser gate for the design-system rules on ALL pages (taken from the built snapshot: every top-level page, `de/*`, hubs, 2 products; `--pages all` = every html) at 1440 and 375, headless Chrome via puppeteer-core, <= 3 workers. It builds a snapshot into a temp dir (`VITE_BASE=/`), serves it on 5193 and removes it afterwards (HMR edits of other people never disturb a run); `--dist <dir>` = an already built dir, `--url` = a running dev server. Refuses to start while hover-gate/another style-gate runs (`--force` overrides; gates in parallel throttle transitions).
Rules (cells in the table: one letter per width; P/F/W/E=exempt/X=error):
- **A1.3** `.icon-ring` in a clickable ancestor must be `--action` and vice versa (decor ring in `.link-card` = WARN, customer decision pending); contact rows (`.footer__contact`...) must use the filled ring, fax must not be a phone-icon `tel:` link.

Rows without an art slot are not checked.
- **A9.5** underlined links: an `a` with computed `text-decoration: underline` at rest outside the allowed places (inline `a:not([class])` inside `p/li/dd/td` prose of FAQ/legal; footer) = FAIL «underlined CTA link; use the button component» (customer 2026-11-13: underlined CTAs do not exist, CTA = `.btn`). - **A1.3 exception (footer fax)**: `style-gate.exceptions.json` has a customer-signed entry (2026-11-13, source: questions c3827e) for `a.footer__contact[href="tel:+494073676290"]`; the fax row keeps the phone icon and tel: link and is reported EXEMPT, not FAIL.

## colour-token-gate.cjs — `npm run audit:colour-token` (customer rule C3, 2026-11-18)
Every text node on a BLUE background (nearest opaque background-colour is blue; photo/canvas surfaces skipped) on every page at 1440 and 375: headings (h1-h6, .t-h*, *__title) must compute to white (`--text-on-accent`); descriptive text (p, .t-lead, .t-body, li, dd, figcaption, outside links/buttons/step lists) must compute to `--text-on-accent-soft` = white 80% over the LOCAL blue (+-1 per channel); all text contrast >= 4.5 (large >= 3). `--inventory` prints the per-element list (selector, role, fg on bg, contrast, expected). Part of `npm run audit`. style-gate (A5.1 colours from tokens) accepts the soft colour because it is a token (probe = default blue; card/supply variants differ by <= 2 per channel).

## static-gate.cjs — `npm run audit:static` (CI, no browser)
Reads the BUILT `dist/` (run `npm run build` first) and needs no dependencies: per page `lang`, title, meta description, absolute canonical, hreflang en/de/x-default (indexable pages that have a DE twin), exactly one h1, heading hierarchy without skips/empty headings, duplicate ids; built CSS/JS: `stroke-dasharray` and JS `dashed: true` = FAIL (three.js defines `LineDashedMaterial` itself, so only usage is searched), `dashed|dotted` borders = WARN (disabled fields, customer decision pending). Exit code 1 on FAIL. `.github/workflows/deploy.yml` runs it after `npm run build` and before `upload-pages-artifact`, so a failing page blocks the deploy. The browser gates (`audit:hover`, `audit:style`) are NOT run in CI: GitHub runners have no configured Chrome/WebGL, a puppeteer setup would add minutes and flaky GPU emulation, and the build there uses `VITE_BASE=/osta/`; they are a local pre-merge check (output pasted in the report). SEO depth stays in `audit:seo`.

## gen-posters.cjs — `npm run poster` (hero posters, customer 2026-11-13: "3D-модель має бути завжди активною"; rework 2026-11-13: "скачок при заміні poster на живу сцену")
Generates the static poster (frame 0) of each above-the-fold WebGL hero scene (Home, About, Services) as `public/assets/img/hero-poster-{home,about,services}-{width}-{ratio}.webp` (transparent webp, <= 160 KB each, `cwebp` quality ladder) and rewrites the `<picture data-hero-picture>` block of `index.html` / `about.html` / `services.html` from the files on disk (the old single-file `<link rel=preload>` is gone: the `<img>` sits at the top of `<body>`, the preload scanner picks the right `<source>`).
WHY MANY FILES: the live scene draws 1-device-pixel lines and fixed-size dots, so its picture depends on the css size and the pixel ratio it is shown at. A poster is a bitmap and matches the live frame only when rendered at the SAME size and ratio, 1:1. Buckets (`BUCKETS` in the script): width centres 375 / 600 / 768 / 1024 / 1280 / 1440 / 1728 / 1920 (media queries by width range) x ratio classes 1 / 1.5 / 2 (+ 3 for phone widths; `min-resolution` 1.25 / 1.75 / 2.5 dppx, highest first). Below 1200 px the live canvas ratio is capped at 1.5 (utils/dpr.js): classes 2 and 3 are rendered at the real device ratio on purpose, so the poster contains the same browser up-scaling of the 1.5 canvas that the live canvas gets.
Method: headless Chrome (SwiftShader) at the bucket's viewport and ratio with prefers-reduced-motion (live scene = exactly frame 0), everything but the canvas hidden, transparent PNG of the `<img>`'s own pixel-snapped device rectangle (About/Services: the poster's layout box; Home: world box 4.5 units around the fit centre), cut to the exact device pixels (no resampling when shown). CSS centres the poster by layout (`inset: 0; margin: auto`, Home by margins), never by `translate`: a transformed image is painted at a fractional position and resampled.
Page side: `img[data-hero-poster][data-poster=...]` inside the scene host, CSS "HERO POSTER" in `components/hero.css`; hand-over = `revealLive()` in `src/utils/hero-poster.js`: the canvas gets `.is-ready` and the poster is hidden in ONE task (one frame; customer 2026-11-14: no cross-fade, no opacity transition, no blend modes; reduced motion = same). What makes the swap invisible is GEOMETRY: the poster must be the live frame 0, same drawn size and position (rule: "точно однакові розміри"). The bitmap is the scene's world box (Home 4.5 units, About 2.4 units, Services drawing +2 %); the generator screenshots the HOST rectangle only (the part the live canvas really covers; the world box may stick out of the host / viewport in stacked layouts, where a screenshot is blank) and pastes it into a transparent bitmap of the box at its true offset. The dev review toolbar (`#__review-host`) is removed before the shot (it was once baked into the 1728/1920 Home posters: static content 38 px bigger than the live one). Quality ladder: lossless alpha first (colour q90 -> q40), NEVER lossy alpha: only colour quality drops, budget 160 KB.
Usage: `node tools/gen-posters.cjs [--only home,about,services] [--widths 375,1440] [--dprs 1,2]` (dev server on 5173 must run; the CSS constant `--poster-ratio` for Services is checked and the script exits 1 on a mismatch; `--widths 0` only rewrites the HTML). A full run is 78 files (about 15 min with three scripts in parallel, one per `--only`). Re-run after ANY change of a scene (geometry, colours, fit, dot size) or of the hero layout.

## poster-swap-gate.cjs — `npm run audit:poster` (poster vs live frame 0: geometry)
Customer 2026-11-14: the jump at the poster -> live swap is a SIZE difference ("статика розміром більше за динаміку"), a fade does not cure it. Per page (home / about / services) x width (1920, 1728, 1440, 1280, 1024, 768, 600, 375 = poster bucket centres) x ratio (1, 2) it renders the poster ALONE and the live canvas frame 0 ALONE (transparent page, reduced motion) and checks: (1) the four edges of the drawn content (every pixel with alpha >= 24, dust specks included) of poster and live differ <= 0.5 css px each (1 device px at ratio 2; width/height = two edges, so up to 1 css px at ratio 2); (2) the bitmap is shown 1:1 (natural size = device size of the <img> box +-1); (3) D = mean abs. RGB difference of both over grey inside the canvas rectangle <= 2.0 (correct posters measure 0.00-0.64 at ratio 1 and up to 1.7 at ratio 2 / phones: lossy webp colour and alpha under the 160 KB budget; D is the secondary check: the +3 % negative test gives D 0.8-3.5 and fails on the edges in 48 of 48 cases); (4) no opacity/blend transition on poster or canvas and the real `revealLive()` shows the canvas (computed opacity 1) and hides the poster in the same task. FAIL texts are plain Ukrainian ("статика більша за динаміку: право на N px"). Options: `--table` (every case with all numbers), `--widths 1512,1680` (in-between widths: the bucket bitmap is resampled there, +-2 px, not gated), `--break scale=1.03` (negative test: poster +3 % must FAIL), `GATE_DUMP=dir` (writes both shots). Dev server needed; refuses to run next to hover-gate / style-gate (`--force`).
